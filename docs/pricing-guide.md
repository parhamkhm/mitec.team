# راهنمای قیمت‌گذاری — برآورد سریع صفحه‌ی اصلی

این سند برای صاحب کسب‌وکار (کسی که اعداد را وارد می‌کند) و توسعه‌دهنده‌ی بک‌اند (کسی که پنل ادمین را می‌سازد) است.

بخش «برآورد سریع» صفحه‌ی اصلی هیچ عدد، برچسب یا توضیحی را در کد ندارد؛ همه را از **یک سند** می‌خواند:

- الان: `project/src/config/pricing.json` (حالت mock)
- بعداً: `GET /pricing` از سرور، که پنل ادمین آن را ویرایش می‌کند (پیشنهاد در `project/API_CONTRACT.md`، بخش ۵ و ۶)
- ساختار و قواعد دقیق: `docs/pricing.schema.json`

هر تغییری در این سند، بعد از بارگذاری دوباره‌ی صفحه، بدون تغییر کد دیده می‌شود.

> **مهم:** همه‌ی اعداد فعلی **نمونه** هستند (`"placeholder": true`) و روی سایت برچسب «اعداد نمونه» دارند.
> بعد از وارد کردن اعداد واقعی، `placeholder` را `false` کنید تا برچسب برداشته شود.

## ۱. هر فیلد چه معنایی دارد

### تنظیمات کلی

| فیلد | معنا |
|---|---|
| `version` | شماره‌ی نسخه؛ با هر ذخیره یکی زیاد می‌شود. سفارش‌ها این شماره را می‌فرستند تا معلوم باشد مشتری کدام قیمت‌ها را دیده است. |
| `updatedAt` | زمان آخرین ذخیره. |
| `placeholder` | `true` یعنی اعداد نمونه‌اند و برچسب «اعداد نمونه» نمایش داده می‌شود. |
| `currency.unit` | واحد پول برای مبلغ‌های کوچک، مثلاً «تومان» → «از ۸۵۰٬۰۰۰ تومان». |
| `currency.divisor` | مبلغ‌های برابر یا بزرگ‌تر از این عدد بر آن تقسیم می‌شوند؛ `1000000` یعنی نمایش به «میلیون». |
| `currency.suffix` | بعد از مبلغ تقسیم‌شده می‌آید، مثلاً «میلیون تومان» → «از ۲۴ میلیون تومان». |
| `currency.from` | کلمه‌ی قبل از مبلغ، مثلاً «از». |
| `display.showPrice` | `false` یعنی هیچ قیمتی در صفحه نیست (نه پنهان؛ اصلاً ساخته نمی‌شود). |
| `display.showDuration` | `false` یعنی مدت زمان نمایش داده نمی‌شود. |
| `display.durationUnit` | چیزی که `days` می‌شمارد؛ فعلاً فقط `workday` (روز کاری). |
| `display.durationLabel` / `durationPrefix` | متن مدت زمان، مثلاً «حدود» + عدد + «روز کاری». |

### متن‌های بخش (`section`)

همه‌ی متن‌هایی که بخش نشان می‌دهد: `eyebrow`، `title`، `subtitle`، `ctaLabel` (متن دکمه)، `disclaimer`،
`placeholderBadge`، `typesLabel` (نام گروه تب‌ها برای صفحه‌خوان)، `pagesTitle`، `pagesDesc`، `addonsTitle`،
`showAll` (دکمه‌ی «همه‌ی موارد» در موبایل)، `totalLabel`.
در `pagesIncluded` و `pagesValue`، `{n}` جای عدد است: `"شامل {n} صفحه"` → «شامل ۳ صفحه».

دو فیلد **اختیاری** هم هست؛ اگر نباشند، همین متن‌های پیش‌فرض نمایش داده می‌شوند:

| فیلد | پیش‌فرض | کجا |
|---|---|---|
| `showAllAddons` | «نمایش همه‌ی امکانات ({n})» | دکمه‌ی زیر فهرست بلند افزونه‌ها؛ `{n}` تعداد همه‌ی افزونه‌های آن نوع است. |
| `showFewerAddons` | «نمایش کمتر» | همان دکمه وقتی فهرست باز است. |

اگر نوعی بیشتر از **۹** افزونه‌ی فعال داشته باشد (در عرض ۱۰۲۴ پیکسل و بیشتر؛ کمتر از آن **۶**)، فقط همان تعداد اول
نشان داده می‌شود و این دکمه بقیه را باز می‌کند. افزونه‌ای که مشتری انتخاب کرده هیچ‌وقت پنهان نمی‌شود.

### نوع سایت‌ها (`siteTypes`) — هر نوع یک «بسته»

| فیلد | معنا |
|---|---|
| `id` | شناسه‌ی ثابت (حروف کوچک انگلیسی و خط تیره). **بعد از انتشار عوضش نکنید**؛ سفارش‌ها با آن ذخیره می‌شوند. |
| `label` | نام تب، هر وقت خواستید عوضش کنید. |
| `active` | `false` نوع را پنهان می‌کند، بدون پاک کردن. |
| `order` | ترتیب تب‌ها (کوچک‌تر = جلوتر). اولین نوع فعال، پیش‌فرض است. |
| `base.title` / `base.subtitle` | عنوان و زیرعنوان کارت پایه. |
| `base.price` | قیمت پایه به تومان (عدد صحیح). |
| `base.days` | زمان پایه به روز کاری (عدد صحیح). |
| `base.pagesIncluded` | چند صفحه در قیمت پایه هست. |
| `base.included[]` | فهرست «همیشه شامل است»: هر مورد `id`، `title` و `desc`. |
| `pages.enabled` | آیا اسلایدر تعداد صفحه برای این نوع نمایش داده شود. |
| `pages.min` / `pages.max` | کمترین و بیشترین تعداد صفحه روی اسلایدر (`min` نباید از `max` بزرگ‌تر باشد). |
| `pages.pricePerExtra` / `daysPerExtra` | هزینه و زمان هر صفحه‌ی **بیشتر** از `pagesIncluded`. |
| `addons` | idهای افزونه‌هایی که این نوع دارد (از فهرست سراسری `addons`). |

«نمی‌دانم» یک بسته نیست؛ زیر تب‌ها یک لینک به سفارش‌ساز است.

### افزونه‌ها (`addons`) — یک بار تعریف، در هر نوع با id

| فیلد | معنا |
|---|---|
| `id` | شناسه‌ی ثابت. |
| `title` / `desc` | عنوان و توضیح کاشی. هر کدام روی سایت حداکثر دو خط نمایش داده می‌شود (متن کامل با نگه داشتن ماوس روی آن). **سقف طول:** عنوان ۲۸ و توضیح ۴۸ نویسه (با فاصله و نیم‌فاصله)؛ پنل ادمین متن بلندتر را نمی‌پذیرد تا شبکه‌ی کاشی‌ها به هم نریزد. |
| `group` | اختیاری. نام گروه، مثلاً «محتوا» یا «فروش و مشتری». اگر حتی یک افزونه‌ی یک نوع `group` داشته باشد، کاشی‌ها زیر عنوان گروه‌ها دسته‌بندی می‌شوند (به ترتیب اولین ظاهر شدن)؛ افزونه‌های بدون گروه اول و زیر عنوان «امکانات بیشتر» می‌آیند. بدون `group`، همه در یک شبکه‌اند. |
| `price` | قیمت به تومان. `0` یعنی کاشی بدون قیمت نمایش داده می‌شود (نه «از ۰»). |
| `days` | زمان اضافه به روز کاری. |
| `active` | `false` افزونه را همه‌جا پنهان می‌کند. |
| `order` | ترتیب ردیف‌ها. |

چون هر افزونه فقط یک جا تعریف شده، قیمتش را یک بار عوض می‌کنید و در همه‌ی نوع‌ها درست می‌شود.

### افزونه‌های فعلی

دوازده افزونه، به ترتیب `order`: فرم تماس (`contact-form`)، پنل مدیریت محتوا (`cms`)، چندزبانه (`i18n`)،
سئوی پایه (`seo`)، ثبت‌نام و ورود (`auth`)، پرداخت آنلاین (`payment`)، نوبت‌دهی و رزرو (`booking`)،
باشگاه مشتریان (`loyalty`)، چت آنلاین (`chat`)، CRM و مدیریت مشتری (`crm`)، اتوماسیون فرایندها (`automation`)
و داشبورد و گزارش تحلیلی (`analytics`).

سه افزونه‌ی آخر (`crm`، `automation`، `analytics`) تازه اضافه شده‌اند و قیمت و زمانشان هم مثل بقیه نمونه است.
فعلاً **برای همه‌ی نوع‌های سایت** فعال‌اند. اگر برای نوعی لازم نیستند، id آن‌ها را از `addons` همان نوع حذف کنید
(در پنل ادمین: از انتخاب افزونه‌های آن نوع برشان دارید).

## ۲. قیمت و زمان چطور حساب می‌شود

```
صفحه‌های اضافه = max(0, تعداد صفحه − pagesIncluded)          (تعداد صفحه بین min و max محدود می‌شود)
قیمت  = base.price + صفحه‌های اضافه × pricePerExtra + جمع price افزونه‌های انتخاب‌شده
زمان  = base.days  + صفحه‌های اضافه × daysPerExtra  + جمع days افزونه‌های انتخاب‌شده
```

افزونه‌ای که غیرفعال است، در فهرست آن نوع نیست یا وجود ندارد، حساب نمی‌شود. اگر `pages.enabled` خاموش باشد،
تعداد صفحه همان `pagesIncluded` است. محاسبه در `project/src/utils/estimate.js` است و سفارش‌ساز هم همان را استفاده خواهد کرد.

### یک مثال (با اعداد نمونه‌ی فعلی)

مشتری «سایت شرکتی» را انتخاب می‌کند، اسلایدر را روی **۴ صفحه** می‌گذارد و «پنل مدیریت محتوا» و «سئوی پایه» را روشن می‌کند:

| بخش | قیمت | زمان |
|---|---|---|
| پایه (`base`) | ۱۰٬۰۰۰٬۰۰۰ | ۱۰ روز |
| ۳ صفحه‌ی اضافه (۴ − ۱) × ۱٬۰۰۰٬۰۰۰ و × ۱ روز | ۳٬۰۰۰٬۰۰۰ | ۳ روز |
| پنل مدیریت محتوا | ۵٬۰۰۰٬۰۰۰ | ۵ روز |
| سئوی پایه | ۲٬۰۰۰٬۰۰۰ | ۲ روز |
| **جمع** | **۲۰٬۰۰۰٬۰۰۰** | **۲۰ روز** |

روی سایت: «برآورد: از ۲۰ میلیون تومان · حدود ۲۰ روز کاری».

## ۳. کارهای رایج

### افزودن یک افزونه

۱. یک مورد به فهرست `addons` اضافه کنید (id جدید و یکتا):

```json
{ "id": "blog", "title": "وبلاگ", "desc": "…", "price": 3000000, "days": 2, "active": true, "order": 13 }
```

۲. id آن را به `addons` هر نوعی که باید آن را داشته باشد اضافه کنید، مثلاً `"addons": ["contact-form", "cms", "blog"]`.

### پنهان کردن یک افزونه (یا یک نوع سایت)

`"active": false` — پاک نمی‌شود و هر وقت خواستید با `true` برمی‌گردد.
برای برداشتن از **فقط یک نوع**، id آن را از `addons` همان نوع حذف کنید.

### جابه‌جا کردن ترتیب

عدد `order` را عوض کنید (کوچک‌تر = بالاتر). برای تب‌ها همان `order` نوع سایت.

### قواعدی که همیشه باید رعایت شود

- idها یکتا و ثابت‌اند (فقط حروف کوچک انگلیسی، عدد و خط تیره).
- عنوان افزونه حداکثر ۲۸ و توضیحش حداکثر ۴۸ نویسه.
- قیمت‌ها و روزها عدد صحیح و بزرگ‌تر یا مساوی صفرند.
- `pages.min` ≤ `pages.max`، و `pagesIncluded` حداقل ۱.
- هر id در `siteTypes[].addons` باید در فهرست `addons` وجود داشته باشد.
- افزونه‌ی «لوگو و برند» اضافه نشود؛ mitec طراحی لوگو و برند انجام نمی‌دهد (سؤالات متداول).

## ۴. پنل ادمین باید چه چیزهایی را قابل ویرایش کند

برای توسعه‌دهنده‌ی بک‌اند. همه‌ی موارد زیر از همان یک سند است و با `PUT /admin/pricing` کل سند ذخیره می‌شود.

1. **نوع سایت‌ها:** افزودن، ویرایش `label`، فعال/غیرفعال، ترتیب؛ و برای هر نوع:
   - کارت پایه: `title`، `subtitle`، `price`، `days`، `pagesIncluded`؛
   - فهرست «همیشه شامل است»: افزودن، ویرایش، حذف و مرتب کردن موردها؛
   - قانون صفحه‌ها: روشن/خاموش، `min`، `max`، `pricePerExtra`، `daysPerExtra`؛
   - انتخاب افزونه‌های این نوع (چندانتخابی از فهرست سراسری).
2. **افزونه‌ها:** افزودن، ویرایش `title` (حداکثر ۲۸ نویسه)، `desc` (حداکثر ۴۸ نویسه)، `group` (اختیاری)، `price`، `days`، فعال/غیرفعال، ترتیب.
3. **پول و نمایش:** `currency` (واحد، تقسیم‌کننده، پسوند، «از») و `display` (نمایش قیمت، نمایش زمان، متن واحد زمان).
4. **متن‌های بخش:** همه‌ی فیلدهای `section`.
5. **وضعیت نمونه:** کلید `placeholder` (بعد از وارد کردن اعداد واقعی خاموش شود).
6. **ایمنی ذخیره:** اعتبارسنجی با `docs/pricing.schema.json` و سه قاعده‌ی `x-rules`؛ خطای `409` اگر کس دیگری در همین فاصله ذخیره کرده باشد؛
   پیشنهاد: نگه داشتن نسخه‌های قبلی و پیش‌نمایش قبل از ذخیره.
